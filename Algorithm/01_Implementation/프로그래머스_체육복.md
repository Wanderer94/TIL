## 💡 핵심 화두 & 직관 (Intuition & Thought Process)

### 1. 그리디 탐색의 정당성 (앞번호 학생에게 먼저 빌려줘야 하는 이유)

- **화두:** 여벌이 있는 학생 $R$이 앞번호($R-1$)와 뒷번호($R+1$) 모두 체육복이 없을 때, 누구에게 먼저 빌려주어야 하는가?

- **결론:** 반드시 앞번호($R-1$)에게 먼저 빌려주어야 합니다.

- 앞번호 학생($R-1$)은 자신의 전 번호 학생에게 이미 빌릴 기회를 상실했기 때문에, 이번 $R$번 학생이 빌려주지 않으면 영영 체육복을 구하지 못합니다.

- 반면, 뒷번호 학생($R+1$)은 추후 $R+2$번 학생에게 빌릴 수 있는 여지가 남아있습니다.

### 2. 예외 조건 처리의 단순화 (본인이 도난당한 경우)

- **화두:** "여벌 체육복을 가져온 학생이 도난당한 경우" 처리.

- **결론:** 이 학생은 빌려줄 수도, 남에게 받을 수도 없는 상태(체육복 1개 소지)가 됩니다.

- **접근 A (List):** `reserve`는 $+1$, `lost`는 $-1$을 더해 상태값을 $1$로 상쇄 처리.

- **접근 B (Set):** 본격적인 탐색 전, 차집합 연산(`-`)으로 두 집합에서 모두 제외.

---

## 1. 핵심 아이디어 (Key Insight)

- **내 접근법 (List 상태 배열 & Padding):** 전체 학생 수를 $N+2$ 크기의 1차원 배열로 선언하고, 인덱스 바운더리 에러(`IndexError`)를 전처리(Padding)로 원천 차단한 뒤 시뮬레이션.

- **다른 접근법 (Set 차집합 & O(1) Look-up):** 여벌을 가졌지만 도난당한 예외 학생을 차집합으로 한 줄에 사전 제거하고, 남아있는 $Reserve$를 기준으로 앞/뒤 학생을 탐욕적으로 탐색.

---

## 3. 복습할 핵심 코드 (Template & Solution)

🔹 [풀이 1] 1차원 배열 패딩 방식 (질문자님의 생각 교정/완성형)

```python
def solution(n, lost, reserve):
    # 인덱스 1~n 활용 및 경계 예외 방지를 위해 n+2 크기 할당 (Padding)
    students = [1] * (n + 2)

    # 상태값 업데이트 (+1, -1)
    for r in reserve:
        students[r] += 1
    for l in lost:
        students[l] -= 1

    # 1번부터 n번까지 탐욕적(Greedy) 처리
    for i in range(1, n + 1):
        if students[i] == 0:
            if students[i - 1] == 2:    # 앞번호 우선 확인
                students[i - 1] -= 1
                students[i] += 1
            elif students[i + 1] == 2:  # 뒷번호 확인
                students[i + 1] -= 1
                students[i] += 1

    # 체육복을 1개 이상 가진 학생 수 카운트
    return sum(1 for s in students[1:n + 1] if s >= 1)

```

🔹 [풀이 2] Set 차집합 활용 파이썬 정석 풀이

```python
def solution(n, lost, reserve):
    # 1. 여벌이 있지만 도난당한 학생 차집합으로 사전 제거
    real_reserve = set(reserve) - set(lost)
    real_lost = set(lost) - set(reserve)

    # 2. 여벌 있는 학생 기준 탐색 (순서 보장을 위해 sorted 사용)
    for r in sorted(real_reserve):
        if r - 1 in real_lost:       # 앞번호 우선 차감
            real_lost.remove(r - 1)
        elif r + 1 in real_lost:     # 뒷번호 차감
            real_lost.remove(r + 1)

    return n - len(real_lost)

```

## 4. 자주 하는 실수 & 오답 회고 (Mistakes & Reflection)

- **내 착각 / 실수 가능성:** 배열 인덱스로 접근할 때 `0`번 학생이나 `N+1`번 학생을 탐색하며 `IndexError`가 발생할 가능성이 존재함.

- **교정 지침:** 배열 조작 시 탐색 범위의 좌우 끝(`i-1`, `i+1`)을 고려해 인덱스 패딩(`n+2`) 기법을 습관적으로 적용할 것.

- **그리디 교훈:** "앞번호부터 빌려준다"는 명확한 탐욕적 선택 기준(Greedy Choice Property)을 세우지 않고 무작위로 빌려주면 최적해를 보장할 수 없음.
